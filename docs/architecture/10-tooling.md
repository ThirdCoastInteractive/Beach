## `cmd/beach` and the skeleton

`beach new <app>` stamps a complete, compiling app: `main.go` (one page, one
Datastar action, one SSE fragment — proving the whole pipe on first `make up`),
`views.templ` with its committed `views_templ.go` compile output, a Makefile
(`help` default; `gen` = `go tool templ generate` + the optional per-app `css`
build + sqlc + `beach ecs gen`, each skipping cleanly when absent; `vet` = gen +
`go vet`; `up`/`down`; `start-db`/`stop-db` with the "never rm-db to fix
migrations" warning), a `go.mod` carrying the templ `tool` directive and a local
`replace` so the app builds against this checkout without network access,
sqlc.yaml (apigen plugin registered), docker-compose (Postgres, ClickHouse
commented out), an `.env` template, and the i18n `catalog.json` + `locales/`.
The framework's design-system `app.css` is generated and served by the
framework; the stamped `css` target exists for an app's *own* extra sheet.

The lint analyzers live in `lint/` and run via `cmd/beach-vet` (exits non-zero
on any finding, so it slots into `make vet` and CI):

- raw Datastar attribute strings and `templ.Attributes{}` literals — typed
  builders are the only sanctioned way
- pgtype imports outside `internal/db`; `google/uuid` outside the sanctioned package
- hardcoded hex/OKLCH in templ or kit CSS (use design tokens); raw icon-font `<i>` elements
- naked `http.HandlerFunc` registered outside `app.Raw`
- **single-head rule**: no `<head>`/`<script>`/`<style>`/stylesheet `<link>`
  outside the base layout; in it, scripts/styles must be `/static/` and
  `<meta name>` must match the allow-list — keeps CSP honest
- **vendoring integrity**: no CDN or naked external URLs in templ/CSS/JS —
  "no external CDNs" is a build failure, not a guideline
- **authz coverage**: mutating queries carry `@requires`, hand-written mutation
  handlers call a principal check, no secret columns in RETURNING
  ([12-auth.md](12-auth.md)); per-line `authz-lint: allow (reason)` markers for
  the genuine exceptions
- **i18n catalog freshness**: literal-only `i18n.T("key")` calls, catalog
  regenerated or the build fails *[shipped as the standalone `beach i18n`
  command, not a `beach-vet` rule — run it in CI beside `beach-vet`]*
- **accessibility** ([06-ui.md](06-ui.md#accessible-by-construction),
  [RFC 06](../rfc/06-accessibility.md)) — three rules, all reading the markup out
  of the generated `*_templ.go` string literals, which is the same markup the
  browser gets:
  - `a11y-img-alt` — an `<img>` with no `alt` at all. A decorative image owes an
    explicit `alt=""`; `driftwood.ImageProps` has `Alt` and `Decorative` so
    there is no image this cannot be satisfied for.
  - `a11y-unnamed-role-img` — `role="img"` with no accessible name. An unnamed
    graphic announces "image" and stops, which is worse than being decorative.
  - `a11y-literal-name` — a hardcoded `aria-label` **inside `pkg/ui` or
    `pkg/chart`**. This one inverts the usual sanctioning: an accessible name is
    content, so the kit's names come from the catalog, while an app's own names
    are already in the app's language and are its own business.

  What `beach-vet` cannot see is CSS, and it cannot see a prop that is only
  filled in at runtime, so the rest of the law is held by tests:
  `pkg/ui/driftwood/contrast_test.go` parses the tokens out of `input.css` and
  asserts every pair the kit paints; `a11y_test.go` runs the naming and
  association laws over every component in the existing `renderCase` maps, and
  again over every component built from its emptiest props — which is where a
  name that depends on an optional field turns out to be missing.

The [14KB rule](06-ui.md#the-14kb-rule) is enforced at runtime instead (dev-mode
over-budget warnings + the example apps' perf gate) — response size isn't knowable
statically.

`beach sql new <name>` stamps the next goose SQL file in a migrations directory: it finds the highest `NNNNN_*.sql` version (or a unique `migrations/` / `chmigrations/` under cwd), claims the next number with an exclusive create so parallel agents cannot both land `00002_*.sql`, and writes the `+goose Up` / `+goose Down` skeleton with `StatementBegin`/`StatementEnd`. Pass `--dir` when more than one migrations folder is in play (Postgres vs ClickHouse, or Beach repo root). `goose create` is the wrong tool here — it timestamps by default and does not serialize version numbers.

`beach ecs gen` runs the component codegen from `components.beach.yaml`
([ECS engine](07-ecs.md#the-portable-core-model)). API wiring is generated by
`beach-apigen` running as a sqlc plugin inside the existing `make gen`
([13-apigen.md](13-apigen.md)) — annotations on SQL queries produce routes,
handler stubs, and NOTIFY plumbing. `beach i18n` extracts and verifies the
translation catalog ([05-services.md](05-services.md#i18n)).

Verification pipeline is framework doctrine, stamped into the skeleton Makefile's
header: `make gen` → `make vet` → `make up` → browser check (no console errors,
change visible, no 404s). A task is not complete until every step passes.

## Testing & performance doctrine

- Integration tests over unit tests (the grug sweet spot); regression test before
  fixing any bug; minimal mocking — sim tests use a real store, db tests a real
  Postgres.
- Sim tests: construct → send → tick → assert. Determinism is the feature.
- Playwright e2e smoke per app, `workers=1` (SSE handshakes don't tolerate parallel
  handshakes against one container).
- driftbottle ships the fan-out benchmark: 5k SSE connections on one container is
  the budget the hub must meet; boardwalk's kill-and-recover test covers the sim
  persistence lanes.
- Perf history as JSONL tracked in git so trends show up in diffs.
