# Architecture 11 — Decisions log

[← docs index](../README.md) · prev: [Tooling & testing](10-tooling.md) · next: [Auth](12-auth.md)

| Decision                 | Choice                                                                                                                                                                                                                                                                                                   | Why                                                                                                                                                                               |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Module layout            | Public API under `pkg/` (`pkg/beach` is the front door, plus `pkg/chart`, `pkg/ecs`, `pkg/ui`, …); private/tooling under `internal/`; binaries in `cmd/`. Revised 2026-06-14 from the original flat-root layout                                                                                                                                                                                                                               | A `pkg/` tree makes the external surface explicit and keeps the root uncluttered; `pkg/beach` stays the package an app touches first                                                                    |
| HTTP framework           | stdlib `net/http` + Go 1.22 `ServeMux` underneath, typed handler shapes on top                                                                                                                                                                                                                           | Zero HTTP dependency — `ServeMux` pattern routing + `net/http` handle SSE fan-out fine; `PageFunc`/`ActionFunc`/`StreamFunc` make the house rules structural; `app.Raw`/`app.Mux()` are the escape hatches |
| UI naming & budget       | `ui` toolkit, one kit (`ui/driftwood` — see the Kit-interface removal below); first response ≤14KB compressed, `ui.Defer` lazy-loads the rest over Datastar                                                                                                                                                                                    | Fits the initial TCP congestion window — first paint in one round trip; deferred sections reserve exact space so no-pop-in holds                                                  |
| ECS engine               | Custom standalone `ecs` package                                                                                                                                                                                                                                                                          | Change ticks first-class (the SSE pipeline's heart); schema-first codegen; zero deps, reusable by any Go project; fast enough for the live slice, not competing on raw throughput |
| ECS vocabulary           | `ecs.Store` + `sim` + `sim.Projection`, not "world"/"render"                                                                                                                                                                                                                                             | Store = what it is (tables + columns); sim = ticks over a store; projection = the event-sourcing word for deriving views from state changes                                       |
| Sim concurrency          | Single writer goroutine + command channel                                                                                                                                                                                                                                                                | No locks, deterministic, testable                                                                                                                                                 |
| System of record         | Postgres, component-mirror tables                                                                                                                                                                                                                                                                        | Legible SQL, sqlc-friendly, no opaque store blob                                                                                                                                  |
| Cross-process bus        | LISTEN/NOTIFY (`pg.Listen`), ids only                                                                                                                                                                                                                                                                    | Single-node honest; NATS seam identified at hub/pg.Listen                                                                                                                         |
| SSE model                | Topics (hub), render-once-per-topic                                                                                                                                                                                                                                                                      | One mental model for every realtime surface; interest management built in                                                                                                         |
| SSE compression          | Gzip in the SSE writer, sync-flush per event                                                                                                                                                                                                                                                             | Middleware buffering was the only real blocker; fragment streams compress 80%+; not `deflate` (raw-vs-zlib ambiguity); per-conn memory is the measured cost                       |
| Sessions                 | Postgres `sessions` table, hardened                                                                                                                                                                                                                                                                      | One datastore for v1 — no Valkey to run; sqlc-queried; RevokeAll = one indexed DELETE; SHA256(token) as PK, per-session CSRF, Rotate() on privilege change                        |
| Passwords                | argon2id `passwords` pkg                                                                                                                                                                                                                                                                                 | m=128MB t=4 p=4, PHC strings, constant-time, rehash-on-upgrade; zero dependencies                                                                                                 |
| Authorization            | Three-table RBAC, `resource:action` permission strings, resolved at login into the session                                                                                                                                                                                                               | Smallest schema that does the job; `beach.Can()` guard + statically verified `@requires` coverage                                                                                 |
| API codegen              | `beach-apigen` sqlc plugin, hypermedia-only                                                                                                                                                                                                                                                              | SQL annotations are the source of truth; six annotations generate beach handler shapes + NOTIFY plumbing; no OpenAPI/JSON emitter                                                 |
| i18n                     | Flat-key catalog + locale JSON + literal-only `T(ctx, key)`, extractor-verified                                                                                                                                                                                                                          | Mechanically verified key set; inert until configured; the catalog is the whole runtime                                                                                          |
| Charts                   | `chart`: pure-Go SVG geometry + templ components                                                                                                                                                                                                                                                         | 22 types, token-themed, accessible, zero client rendering — already obeys the ui laws; live updates ride the hub                                                                  |
| Analytics store          | ClickHouse via `ch`                                                                                                                                                                                                                                                                                      | The right tool for append-only observations; Postgres stays system of record; ingest is fire-and-forget, optional everywhere                                                      |
| Validation apps          | Trio: boardwalk (game/sim), driftbottle (chat/hub), pantry (ERP/apigen+analytics)                                                                                                                                                                                                                        | One app can't honestly exercise every package; each showcases a different slice, and the unused cells in the coverage matrix prove modularity                                     |
| Scaffold                 | `beach new` stamps files into the app                                                                                                                                                                                                                                                                    | Apps own their Makefile/sqlc.yaml; no runtime magic, no hidden codegen                                                                                                            |
| Service migrations       | Out of scope                                                                                                                                                                                                                                                                                             | The framework proves itself greenfield first; migrating existing services is its own program                                                                                      |
| Distribution (2026-06-12) | Private/internal module — not published (by choice, not licensing)                                                                                                                                                                                                                                      | No longer vendors any non-redistributable asset: the client is the free Datastar core (`datastar.js`, Apache-2.0) and CSS is generated locally. Kept private as a product decision; nothing now blocks open-sourcing if that changes |
| CSS system (2026-06-12)  | Tailwind v4 + `rybitten` palettes generating CSS custom properties, no utility classes in markup; replaced Stellar/Datastar Pro                                                                                                                                                                          | One generated `app.css` from `pkg/beach/view/css/input.css`: surface/ink/edge/accent/role tokens plus the 15 `--color-series-a…o` series colors (via the `rybitten` RYB color model — the vocabulary later settled in [06-ui.md](06-ui.md#tokens)), type/space/border/shadow/z-index/aspect/motion tokens. The kit writes semantic `dw-*` classes on tokens, not utility classes; output is plain CSS, served from the framework static tree |
| Client interactivity     | HTML + CSS first; Datastar is the only JS, for server round-trips only                                                                                                                                                                                                                                   | The platform does disclosure/dialog/tabs/popovers/toggles without script — CSS-native components work before any bundle loads and can't break on a script error; JS earns its place only for hypermedia (fragments, signals, SSE) |
| Drop Valkey (2026-06-10) | Sessions moved from Valkey to a Postgres `sessions` table; Valkey removed from the stack                                                                                                                                                                                                                 | `cache`/`i18n` were already in-process, so sessions were Valkey's only user; one datastore in v1 is the grug win                                                                   |
| v1 slimming (2026-06-09) | Cut: ecs cross-language emitters + cross-runtime snapshot promise; auth attestation/audit chain/multiplexer/groups/deny/scopes/field-path perms; session realms; apigen OpenAPI + 5 JSON-shaping annotations; chart legend toggles; query-DSL helpers; separate pgnotify package; fluent `Patch` builder | Every cut was speculative weight no example app feeds                                                                                                                           |
| templ everywhere (2026-06-12) | Every view — framework, kit, examples, scaffold — is a `.templ` component compiled by `templ generate` (a Go tool, run by `make gen`); generated `*_templ.go` is committed                                                                                                              | Hand-written `templ.ComponentFunc` closures were write-only string building; the DSL is checkable, diffable markup, and committing the output keeps plain `go build` working      |
| Kit interface removed (2026-06-12) | No `ui.Kit`, sub-interfaces, registry, or `Config.Kit`/`c.Kit()`; one kit, `ui/driftwood` — exported package-level templ components called directly, props structs in `driftwood`; `ui` keeps `Icon` + `Defer`                                                                     | An interface with one implementation is indirection, not abstraction; direct calls are compile-checked where the registry could only fail at runtime; a second kit, if ever real, forks the package |
| Charts re-ported + client layer (2026-06-12) | `chart/` re-ports Atlas's chart system as one package — geometry `.go` + render `.templ`, 22 types + the SSE bar race, `Chart*Fragment` wrappers, server-built `data-tip` tooltips — plus a built-in JS interaction layer (`chart.js` modules: tips, hovers, toolbar)    | The old `io.Writer` SVG funcs + golden testdata were a parallel render path; tooltips/crosshairs/theme toggles genuinely need script, so the "no client script for charts" absolute is retired — the layer is progressive enhancement over SSR + SSE, never required to render or animate |
| Sync boundary (2026-06-26) | No sync engine, ever. the-beach is hypermedia — the wire unit is rendered HTML, not client-side data — so adopting one (client holds a data replica) would convert the SSR core into a worse SPA. Read-path liveness rides the [hub](04-hub.md) (NOTIFY → re-render → publish); conflicts are last-write-wins at the server, designed out; offline writes are the exit condition, not a feature. Full reasoning in [20-sync.md](20-sync.md) | We already sit in the "generalizes" quadrant of Siidorow's sync-engine taxonomy (Aalto 2026): server-authoritative, always-online, server-owned writes, server-pushed deltas. The HTML sync unit also dissolves partial replication and client-side schema evolution. The one inherited problem — read freshness — is solved per-surface, not by importing a client-side data replica |
| Demo cmds deleted (2026-06-12) | `cmd/demo`, `cmd/barrace`, `cmd/gamuts` removed; `cmd/beach`, `cmd/beach-apigen`, `cmd/beach-vet` remain. Showcase value moved to `ui/specimen` (mounted at `/specimen` by all four examples), the live race to boardwalk, the gamut preview onto the specimen                           | Demo binaries drift the moment the framework moves; the examples already run under test and in real browsers, so the showcase rides them for free                                  |
| Accessibility target (2026-08-28) | **WCAG 2.1 Level AA is a framework law**, stated in [06-ui.md](06-ui.md#accessible-by-construction) as the fifth clause beside the performance laws, and it is what the roadmap's "a11y clean" gate now means. Full audit and exceptions in [RFC 06](../rfc/06-accessibility.md) | The gate existed and was undefined, so nothing checked it and the kit was wrong in the places instinct does not reach — a nameless `role="img"` on 26 charts, a `role="tablist"` over things that were not tabs, three tokens under the contrast bar, and every SSE-pushed status message silent. AA is the bar procurement and law actually ask for; AAA has criteria the palette and the no-script rule cannot meet honestly |
| Accessible names are translations (2026-08-28) | The kit emits no literal `aria-label`. Every name resolves through `i18n.T(ctx, "ui.a11y.…")` against the framework's embedded catalog, enforced by `beach-vet`'s `a11y-literal-name`. New import edge: `ui/driftwood → i18n` | A name a screen reader reads out is content — announcing "Close" on a Spanish page is as wrong as an untranslated heading. The alternative was a private string table in the kit, which is a catalog with worse tooling. `i18n` is inert until configured, so a monolingual app pays nothing for the edge |
| Field associates via context (2026-08-28) | `Field` rebinds `ctx` for its subtree with the ids of the help and error text it rendered; the controls read them back into `aria-describedby`/`aria-invalid`. With no `For`, `Field` renders `<fieldset>`/`<legend>` instead of a label pointing at nothing | A templ component cannot reach into an opaque `{ children… }` to add an attribute, and making callers repeat matching ids by hand is precisely the manual synchronisation that leaves real forms unlabelled. Using templ's own context mechanism meant **no call site changed** — every existing `@Field { @Input }` became conformant where it stood |
| The live region is the framework's (2026-08-28) | `driftwood.Shell` renders an empty polite region at `driftwood.ToastTarget` on every page; `Toast` dropped its own `aria-live`; `beach.Patch{Announce: "…"}` pushes a status message into it. `beach.ToastTarget` is now an alias of the kit's constant | A live region that arrives together with its content is not announced, so every server-pushed status message in every beach app was silent. Fixing it needed the region to ship in the first response — which only the shell can do. Pure hypermedia: no new client script |
| Accent darkened, not re-typed (2026-08-28) | `--color-accent` moved along the same rybitten munsell blue axis (hue 240, sat 1.0) from lightness 0.445 to 0.290: `#3b8ea8` → `#3d7c82`. Hover, soft and `--color-line-strong` moved with it; button text stays white, and hover now darkens rather than lightens | White on the old accent was 3.74:1 where SC 1.4.3 needs 4.5 — the primary button, on every page. Darkening keeps white type, which is what every other solid role button uses. The passing window is narrow (relative luminance 0.164–0.183: white text above, focus-ring contrast below), and hover has to darken because SC 1.4.3 applies to text as displayed, hover state included |
| Tabs is a radio group, honestly (2026-08-28) | `Tabs` dropped `role="tablist"`, renders its panels, and keeps its radios focusable (clipped, not hidden) with the focus ring relayed to the label by a per-index ladder in `input.css`, capped at `MaxTabs` = 8 | The ARIA tabs pattern needs roving tabindex and arrow-key handling — script, which the HTML-and-CSS-first law rules out for a local interaction. A `role="tablist"` whose children are not tabs is worse for a screen reader than no role, while a native radio group brings correct arrow-key navigation and announcement for free. It also rendered no panels at all, which the rewrite fixed |
| Contrast is a test (2026-08-28) | `rybitten` gained `Luminance`/`Contrast`/`ParseHex`/`Over`; `pkg/ui/driftwood/contrast_test.go` parses the real tokens out of `input.css` and asserts every pair the kit paints. Readable text uses a token, never a raw `zinc-*` utility, and `opacity` is not a de-emphasis tool | Contrast is a property of pairs, so a token sheet cannot be checked by looking at it. Putting the pairing decision in a test is the same posture as the 14KB rule: measured, not reviewed. The raw-utility and `opacity` bans exist because both move a color the tokens no longer describe, which is exactly what the test cannot see |
| Zero-value conformance (2026-08-28) | Every component must be accessible built from its emptiest props, held by `TestZeroValuePropsAreStillAccessible`. A name that comes from an optional prop needs a fallback (`Progress`, `Composer`, `MenuButton`, `Popover` take one from the catalog; `InputGroup` borrows the button's label), and a role that cannot be named is dropped (`Segmented`, `ButtonGroup`) | The demo-shaped suites render components as they are meant to be used, which is the wrong place to look for this: a component that names itself from a prop is conformant when the prop is set and silently broken when it is not — and an omitted optional field is the likeliest thing to happen in an app. It found six defects on the first run |
| aria-label="" is banned (2026-08-28) | An ARIA name attribute is written conditionally, never unconditionally from a possibly-empty prop. `IconButton` omits both `aria-label` and `title` rather than emitting them empty | An empty name is not a name — the control stays unlabelled while looking, in a review and to a linter, exactly like the case has been handled. Omitting it degrades to "nameless button", which the naming law catches |
| Reactive ARIA states use ariaBoolExpr (2026-08-28) | A `data-attr`-bound ARIA state wraps its expression to yield the strings `'true'`/`'false'` | Datastar writes a boolean-valued `data-attr` the way HTML writes a boolean attribute: empty value when true, attribute removed when false. Correct for `disabled`; for an ARIA state a removed `aria-pressed` does not mean "not pressed", it means "not a toggle button" — so the control stopped being one the moment it was switched off |
| AppShellProps.Embedded (2026-08-28) | One flag marking a Shell as a preview inside another page: no bypass link, no `main` landmark, no live region. `driftwood.Main` exports the landmark on its own for a page that builds its own frame. Replaced the speculative `NoLiveRegion` flag added earlier in the same change | A page has exactly one main, one bypass link and one live region. The specimen embeds a Shell to show the frame, which duplicated all three along with their ids — worse than having none, since a patch aimed at the live region then has two targets |
| Reflow to 320px is part of the law (2026-08-28) | Control rows wrap, the two-column form stacks below `sm`, flex children holding inputs carry `min-w-0`, and a data table scrolls inside `.dw-table-scroll` rather than widening the document | SC 1.4.10 exempts data tables from reflowing but not from staying in their own container: a table that widens the page makes every other line of text on it scroll sideways too. The two-column form was the worse offender — a fixed 12rem label track left 34px for the control at 320px, which is not a narrow form but an unusable one |
| No aria-expanded on popover triggers (2026-08-28) | `MenuButton`, `Popover` and the `<dialog>` triggers carry `aria-haspopup` and `aria-controls` — both true whatever the panel is doing — and deliberately not `aria-expanded`. `chart-toolbar.js` does write it, because it owns its own open/close | Open/close is the platform's `popovertarget`, with no script to keep an attribute in step, so a written `aria-expanded` would freeze at "false" and start lying the moment the panel opened. Browsers already derive expanded state from `popovertarget`. Same reasoning as "no role you cannot honour": a stale ARIA state is worse than an absent one |
| Charts named by variadic option (2026-08-28) | `Chart*Fragment(id, data, opts ...FigureOpt)` with `chart.Label` / `chart.Describe`, rather than a `Label string` field on each of the 26 chart input structs | A variadic parameter appends to an existing signature without breaking a call site, the name belongs to the `<figure>` that carries it rather than the geometry that does not, and `Describe` — the text alternative, the part that actually conveys the chart — has somewhere to live that a `Label` field would not have given it |
| Motion coverage is a test, not a review (2026-08-28) | `TestEveryAnimationRespectsReducedMotion` extracts every animating selector from `input.css` and fails unless each is named inside a `prefers-reduced-motion` block | The failure mode is a forgotten rule, not a wrong one: someone adds a pulse, it looks right, and the person it makes ill never files a bug. Checking that the media query *exists* would have passed while `.ui-skeleton` was uncovered — which is what this found on its first run |
